## 1. 一笔转账的七个阶段

```text
① 构造        ② 签名            ③ 广播           ④ 入池
钱包组装字段 → keccak256(RLP)  → eth_sendRaw-   → 节点校验：
nonce/gas/     得摘要，secp256k1   Transaction      签名恢复·nonce·
to/value/data  私钥签出 v/r/s     （HTTP POST）     余额(本金)·gas 下限
   │              │                  │                │
   │  本地计算     │  私钥永不离开本机  │  任何节点可收     │  不过 → RPC 错误，无 hash
   ▼              ▼                  ▼                ▼
⑤ 排序出块     ⑥ EVM 执行        ⑦ 终结
QBFT proposer  扣本金·烧 gas·    ≥quorum(3/4) 验证者签 commit 证书
轮值提案       写状态·发日志     → 入块即最终，无重组
（5s 一块）    revert → status=0  （公链这里才是「N 个确认」）
```

与 Java 后端对照（帮助建立直觉，**不是等价**）：

| 阶段 | 近似类比 | 关键差异 |
|------|----------|----------|
| ①② 构造+签名 | 客户端组装请求 + 数字签名 | 签名覆盖**全部字段含 chainId**，改一个字节即失效 |
| ③④ 广播+入池 | 网关收请求 + 参数校验 | 校验失败**没有回执**，只有 RPC 错误；池是全网共享的 |
| ⑤ 排序 | 消息队列定序 | 定序权在 proposer 轮值，不在客户端；nonce 保证同账户顺序 |
| ⑥ 执行 | 事务处理 | **失败也烧 gas**（status=0），不像数据库回滚不收费 |
| ⑦ 终结 | 事务 commit | QBFT 是确定性终结；公链是概率性（越深越难翻） |

## 2. 字段字典（速查）

详细实测值见附录，这里给「是什么 / 谁定的 / 出错会怎样」：

| 字段 | 是什么 | 谁定的 | 出错会怎样 |
|------|--------|--------|------------|
| `type` | 0=legacy(EIP-155)，2=EIP-1559 | 钱包 | 零 gas 链上 type-2 费用估算易踩坑（B04：1 wei 下限卡池） |
| `chainId` | 链标识，进签名摘要 | 创世配置 | 换链重放直接失败（EIP-155 的全部意义） |
| `nonce` | 账户交易序号（从 0） | 钱包查 `eth_getTransactionCount` | 太低→拒；太高→排队；同号→后到顶掉先到 |
| `from` | **ecrecover(v/r/s) 恢复出来的地址** | 密码学 | 不是声明字段！节点只认恢复结果 |
| `to` | 收款方；`null`=部署合约 | 钱包 | 部署时合约地址=keccak(RLP(deployer,nonce))[12:] |
| `value` | 转账面值（wei） | 钱包 | `value > balance` → 池层拒（-32004），**零 gas 也查** |
| `gasLimit` | 愿烧上限 | 钱包/估算 | 原生转账恒 21000；不够→out of gas，status=0 |
| `gasPrice` | 单价（本链恒 0） | 钱包（须显式 0） | 非 0 会要求余额付手续费 |
| `input` |  calldata：4 字节选择器+ABI 参数 | 钱包/合约 ABI | 选择器=keccak256("transfer(address,uint256)")前 4 字节=`0xa9059cbb` |
| `v/r/s` | ECDSA 签名三元组 | 私钥计算 | r/s 须在曲线阶内；v 含 chainId 信息（EIP-155） |
| `status`（回执） | 1 成功 / 0 revert | EVM | **0 也是入块交易**，gas 照烧，状态不动 |
| `gasUsed`（回执） | 实际烧掉 | EVM | 失败交易也有（本手册 T6=24419） |
| `logs`（回执） | 事件：topics[0]=事件签名哈希，indexed 参数进 topics，其余进 data | 合约 emit | Transfer=`0xddf252ad…`；mint 的 from=0x0 |
| `blockHash/Number` | 所在块 | proposer | QBFT 下入块即最终 |

## 4. 失败分类学（四层，各有不同的「尸体」）

| 层 | 例子 | 有没有 tx hash | 有没有回执 | 钱动了吗 | gas |
|----|------|----------------|------------|----------|-----|
| RPC/池层拒绝 | T6 的对照实验：EMPTY 发 value=1 wei | **无**（-32004 INSUFFICIENT_FUNDS） | 无 | 没动 | 不烧 |
| 治理层拒绝 | 60s 内重复领水 | 无（HTTP 429） | 无 | 没动 | 不烧 |
| EVM revert | **T6**：transfer 超余额 | **有** | **有，status=0** | 没动 | **烧 24419** |
| 成功 | T1–T5/T7/T8 | 有 | 有，status=1 | 动了 | 烧（本链 fee=0） |

三个必须建立的直觉：

1. **「交易失败」≠「请求失败」**。T6 在链上有一切（hash/块/回执），只是 status=0。
   ethers v6 的 `tx.wait()` 会把它当 `CALL_EXCEPTION` 抛出——回执挂在异常对象上，别把异常当网络错误（本项目实测踩到）。
2. **revert 原因不在回执里**。取法：在入块高度重放 `eth_call`（`parseTx` 已实现），
   解码 `0x08c379a0`（Error(string)）前缀 → T6 得到 `"balance"`，对应 DemoToken.sol 的 `require(balanceOf[from] >= value, "balance")`。
3. **失败也烧 gas**。EVM 已执行的计算不退钱——这是抗 DoS 设计，不是 bug。公链上这就是「失败交易还要手续费」的来源；本链单价 0 所以 fee=0，但 gasUsed 照记。

## 5. 签名与防重放（为什么 from 不可伪造）

- 摘要 = `keccak256(RLP(nonce, gasPrice, gasLimit, to, value, data, chainId, 0, 0))`（legacy，EIP-155）。
- 节点收到交易后 **ecrecover(摘要, v, r, s) → 地址**，这个地址就是 from；签名不对=换个 from=别人的钱动不了。
- 防重放三件套：**chainId**（跨链重放失败）、**nonce**（同链重放失败）、**签名覆盖全字段**（改 value/to 重放失败）。
- 本手册每笔交易都做了恢复对账（附录 `ecrecover` 行），T8 的 v=28（奇偶性+27，legacy 写法）。
- P05 的 EIP-2612 permit 会把这套「签名即授权」搬到 ERC20 授权上，域分隔（EIP-712）是同一思想的延伸。

## 6. 零 gas 的准确语义（本链特有，公链不适用）

**免的是手续费，不是本金。** 实测两条边界：

- T7：EMPTY 余额 0，发 `value=0` → 入块成功（`--tx-pool-enable-balance-check=false` 免掉 gas 成本检查）。
- 负例：EMPTY 发 `value=1 wei` → 池层直接拒 `INSUFFICIENT_FUNDS`（`value > balance` 照样查）。

推论：本链上「领水」验证的不是「有钱才能付 gas」，而是**资产分发与水龙头治理**语义
（运营方创世预存 → 链下 faucet 按规则分发 → 链上余额可查 → 冷却/预算可审计）。

## 7. 终结性：QBFT 与公链的根本差异

| | Sepolia（PoS） | 本联盟网（QBFT） |
|--|----------------|------------------|
| 入块后 | 还可能重组，等 N 个确认/finalized | **入块即最终**（≥3/4 验证者签 commit 证书） |
| 「确认数」 | 安全参数 | 只是链头距离，**不是安全参数** |
| 出证口径 | N 确认后出证 | 区块终结证明 + blockHash/txRoot（见 shared/evidence） |
| 代价 | 无停链风险 | n=4 挂 2 台即停链（quorum=3）；排障看**高度涨不涨**，别看进程在不在 |

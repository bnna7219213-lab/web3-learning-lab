# 02 · 版本与编译：OZ 选型、evmVersion、指纹与测试工具语义

> 日期：2026-11-11 · 本篇记录 P05 开工当天踩到的五个「版本/工具语义」坑，全部有实测出处。

## 1. OZ v5.7 在 London 级链上编译失败 → 锁 v5.0.2

联盟网 genesis 只开到 London（B04 实测：cancun 字节码的 PUSH0 会让部署 status=0）。
用 `FOUNDRY_PROFILE=consortium`（evm_version=london）编译 OZ **v5.7.0** 时直接编译错误：

```text
Error (7755): The "mcopy" instruction is only available for Cancun-compatible VMs
(you are currently compiling for "london").
  --> lib/openzeppelin-contracts/contracts/utils/Bytes.sol:124:13
```

`mcopy` 是 Cancun 指令，OZ v5.7 在 `Bytes.sol` 的内联汇编里**无条件**使用它——
汇编指令在编译期就按 evm_version 校验，与函数是否被调用无关。而 `Bytes.sol` 在
ERC20Permit→EIP712→Strings 的依赖链上，绕不开。

决策：**全项目锁 OZ v5.0.2**（汇编只含 Shanghai 前指令，london 可编）。
这正是开发计划「工具链锁死一个季度」的意义：同一份源码要在 anvil(cancun) 与联盟网(london)
两个 profile 下都编得过，OZ 版本就不是「越新越好」。vendored 在 `lib/openzeppelin-contracts/`
（只留 contracts/ 与 LICENSE，mocks 剔除，.gitignore 有净化规则）。

## 2. OZ v5 的接口迁移：错误与事件不在 ERC20 合约里

从 v4 教程抄代码会连撞三处（本次实测）：

| v4 写法 | v5 实际位置 |
|---------|-------------|
| `ERC20.ERC20InsufficientBalance` | `IERC20Errors`（interfaces/draft-IERC6093.sol） |
| `ERC20.ERC20InvalidReceiver` / `ERC20InsufficientAllowance` | 同上 |
| `emit ERC20.Transfer(...)` / `ERC20.Approval` | `IERC20`（事件声明在接口） |

permit 的错误仍在 `ERC20Permit` 本体（ERC2612ExpiredSignature / ERC2612InvalidSigner）。
**读错误声明的源码位置，比背教程可靠。**

## 3. immutable 与字节码指纹：out/ 产物 ≠ 链上 code

面板做「链上跑的是不是这份编译产物」核对时，长度相同（5703 字节）但逐字节不等。
原因：`CAP` 是 immutable，**部署时才把值回填进字节码**；out/ 产物的对应槽是占位零。
解法：按产物的 `deployedBytecode.immutableReferences` 把槽位掩掉再比（frontend/app.js）。
推论：P04 的 `deployedBytecodeHash` 自证对含 immutable 的合约，必须记录「掩槽后」的口径，
否则同一份代码两次部署（不同 CAP）指纹不同是**预期行为**，不是代码被改。

## 4. forge expectRevert 是精确匹配，前缀匹配用 expectPartialRevert

`vm.expectRevert(SomeError.selector)` 对**带参数**的错误会失败，即使 selector 完全一致
（实测：raw revert 前 4 字节 == 期望 selector，仍报 `Error != expected error`）。
forge 的语义：expectRevert(bytes4) 精确匹配整段 revert 数据；要只断言错误类型用
`vm.expectPartialRevert(selector)`。permit 重放类测试里恢复出的 signer 不可预测，
只能前缀匹配；signer 可预测时（wrong-signer 用例）仍用全参数精确匹配。

## 5. 两个 Solidity/Foundry 小坑

- **`after` 是 0.8.28 保留字**：变量名 `bytes32 after` 编译报 `Expected ';' but got reserved keyword`。
- **`vm.prank` 只作用于下一次外部调用**：`vm.prank(admin); token.grantRole(token.MINTER_ROLE(), x)`
  里的 `token.MINTER_ROLE()` 是外部 view 调用，会**消耗掉 prank**，导致 grantRole 以默认 sender 执行而权限拒绝。
  解法：角色常量先读进状态变量，prank 与目标调用之间不插任何外部调用。

## 一句话总结

合约工程的「版本」有四层：solc / evmVersion / 依赖库 / 测试工具语义。
任何一层漂移都会以「编译错误、部署 status=0、指纹对不上、测试假失败」四种面貌出现——
**把它们各自锁死并写进部署记录，指纹自证才成立。**

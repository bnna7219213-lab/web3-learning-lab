# 01 · 全栈闭环：钱包层、事件驱动刷新与失败诊断

> 配套代码：`frontend/src/{wallet.js,App.jsx}` · `src/Voting.sol` · 日期：2026-11-11
> 栈：Vite + React 18 + wagmi 2 + viem 2（选型偏离说明见 §6）

## 1. 钱包层：两条路径，一套 EIP-1193 代码

DApp 只认 wagmi 的 `injected()` 连接器，即只认 `window.ethereum` 的 EIP-1193 接口：

| 路径 | window.ethereum 来源 | 签名者 |
|------|---------------------|--------|
| MetaMask | 浏览器扩展注入 | 扩展内密钥（用户自持） |
| 本地演示钱包 | `installDemoProvider()` 安装的 shim | **anvil 节点代签**（eth_sendTransaction 转给解锁账户，前端零私钥） |

shim 实现 `eth_chainId / eth_accounts / eth_requestAccounts / eth_sendTransaction /
wallet_switchEthereumChain` + `accountsChanged / chainChanged` 事件，其余方法转发 anvil RPC。
**它不是第二套钱包逻辑**：DApp 业务代码对两条路径完全无感，因此无扩展环境里的 E2E
走的就是 MetaMask 会走的代码路径。shim 额外暴露 `_setAccount / _setWrongNetwork`
两个演示开关（业务代码不依赖），用于在 UI 里复现「切账户」「切错网络」。

读请求不走钱包：wagmi 的 transports 直连 anvil RPC（`pollingInterval: 1000`），
钱包只负责账户与写签名——读写分离是 wagmi 的默认架构，也是联盟网/公链通用的形态。

## 2. 事件驱动刷新 + 轮询兜底

- `useWatchContractEvent(ProposalCreated / Voted)` → 事件流面板追加 + `queryClient.invalidateQueries()`
  失效全部 readContract 缓存（wagmi 官方模式）。
- **实测教训**：只靠 invalidate 时，提案计数查询出现过不重取（缓存语义与观察者生命周期交织，
  现象是事件到了、列表不动）。最终给四个读查询加 `refetchInterval: 2000` 兜底：
  **事件负责即时性，轮询负责正确性**——与 B03 索引器「扫块 + 游标」的双保险同构。
- 跨客户端验证：用 `cast send --unlocked` 从浏览器之外的账户投票，页面**不重载**即出现
  Voted 事件与 tally 变化（实测 tx `0x374bf6ef…`，块 #17）。

## 3. 失败诊断：三层错误，三种文案

| 层 | 例子 | UI 表现 |
|----|------|---------|
| 连接/网络层 | chainId ≠ 31337 | 红色横幅「网络不匹配…已禁用全部写操作」+ 切换按钮（实测 chainId 1 → 拒绝 → 切回恢复） |
| 发送层 revert | 钱包/节点估算即拒 | `explainError` 逐层 cause 找 revert data → ABI 解码 → 中文文案 |
| **挖块后 revert** | status=0（如 ZeroDuration） | 回执不带 reason → **在入块高度重放 eth_call** 取 reason（P03 手册 §4 同款技术）→「入块但执行失败：投票时长必须大于 0」（实测 tx `0xd1e4bba9…` #13 status=0） |

自定义错误 → 中文映射表在 `App.jsx ERROR_TEXT`（AlreadyVoted/VotingClosed/ProposalNotFound/
OwnableUnauthorizedAccount/EmptyTitle/ZeroDuration）。双投与过期在 UI 层另有前置禁用
（投过/截止后按钮 disabled），合约层仍独立强制——**前端禁用是体验，合约校验才是安全**。

## 4. ABI 与部署记录自动下发

`frontend/src/App.jsx` 直接 `import "../../abi/Voting.json"` 与
`"../../deployments/31337/Voting.json"`（vite `server.fs.allow` 放开到仓库根）。
deploy.sh 重新导出 ABI / 重新部署后，dev server 经 HMR 自动跟随——**禁止手抄 ABI** 在构建层成立。
注意：页面在 vite 根路径 `/` 时 `fetch("../deployments/…")` 会被浏览器归一化成 `/deployments/…`
而 404（P05 面板在多级路径下没暴露这个问题）——import 而非 fetch 是正解。

## 5. 合约侧最小闭环

owner 建提案（标题非空、时长 >0、带 deadline）→ 一人一票 yes/no（hasVoted 映射）→
链上 tally。13 项测试含边界（deadline 当刻仍可投）、双投换立场仍拒、跨提案票权独立、
fuzz 计票守恒。无代币加权/委托/时间锁——P19 的主题，这里刻意不做。

## 6. 选型偏离与 MetaMask 实测边界

- **Vite 而非 Next.js**：本地实验台无 SSR/路由需求，Vite 启动与 HMR 更快；roadmap 的「React/Next」取 React。
- **_plain CSS 而非 Tailwind**：与 P04/P05 面板视觉一致，零额外构建链。
- **MetaMask 路径本会话未实测**：自动化浏览器无扩展安装能力。injected 连接器为 wagmi 标准件，
  演示 shim 已覆盖同一 EIP-1193 表面；真实 MetaMask 验收步骤见 README（添加 Anvil 网络后连接即可），
  留待有扩展的环境补一次人工实测。**不把未实测写成已实测。**

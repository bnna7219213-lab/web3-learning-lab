# 02 · B04：把同一份合约部署到 Besu QBFT 联盟网要注意什么

> 前提：联盟网已按 `shared/consortium-network/` 起好（`21-up-native.sh` → node-1 RPC 在 `http://127.0.0.1:8551`）。
> 本文所有"注意"都来自 P04 在 anvil 上的实测 + Besu 官方文档，**联盟网部分尚未实机验证**，跑通后请回填实测输出。

## 一、命令层面只改一处

```bash
cd projects/P04-HelloContract基础
bash script/deploy.sh consortium        # profile 换成联盟网
```

`env/consortium.env` 里三件事和 anvil/sepolia 不同：

| 键 | 值 | 为什么 |
|----|-----|--------|
| `GAS_MODE` | `zero` | deploy.sh 会加 `--gas-price 0`；否则 forge 按 baseFee 估算出非零值，与零 gas 链不一致 |
| `EXPLORER_VERIFY` | `false` | 没有公网浏览器可 verify |
| `CHAIN_ID` | 与 genesis 一致 | 不一致时 forge 会拒绝或签出错链 ID 的交易（跨链重放的根因） |

## 二、五个可能卡住你的点（按出现概率排序）

### 1 部署账户不在账户白名单里
如果联盟网开了 `accounts-allowlist`，未授权地址发交易会被节点直接拒。
表现：`eth_sendRawTransaction` 返回类似 "sender not in allowlist" 的错误，而不是 revert。
处理：走 `scripts/40-add-member.sh` 的账户授权流程，或试点阶段先只开节点白名单。

### 2 单笔 gas 上限（EIP-7825）
合约一大（P07 的 NFT 市场、P08 的代理 + 实现两连部署）就会撞 `16,777,216` 的单笔上限。
处理：genesis 的 `qbft.pertxgaslimit = 0`（本底座已设）。
**验证方法**：部署后调 `deployedBytecodeHash` 与本地 `out/` 产物比对，一致才算成功——不要只看"没报错"。

### 3 某个节点 `min-gas-price` 不为 0 → 交易静默消失
官方 danger：任何节点最小 gas price > 0 都会**静默丢弃**零 gas 交易。
表现：交易 hash 拿到了，但永远查不到 receipt。
处理：`scripts/30-smoke-test.sh` 断言 `eth_gasPrice == 0`，并且**每个节点都要跑一遍**（不是只跑 node-1）。

### 4 chainId 与地址派生
如果用 Create2 预计算地址（P08），chainId 变了地址就全变。
联盟链上线后**永远不要改 chainId**，并把 chainId 登记进交付文档。

### 5 没有 verify 通道 → 用指纹自证
交付时给客户的三件东西：
```
地址 + deployedBytecodeHash + 源码版本（git commit）
```
客户可独立复核：
```bash
cast code --rpc-url http://<联盟网RPC> <合约地址> | xxd -r -p | cast keccak
# 与 deployments/<chainId>/Counter.json 的 deployedBytecodeHash 比对
```
> 这条命令我没在联盟网上实跑（`cast code` 的输出格式需实测确认），跑通后回填。

## 三、B04 相对 P04 的额外验收（对齐分支共用四条）

| 验收 | P04 已做 | B04 要补 |
|------|----------|----------|
| 多成员账户 | 单账户 | 用两个成员账户各部署一次，nonce 互不干扰 |
| 零 gas | 不适用 | `eth_gasPrice == 0` 且部署成功、receipt 可查 |
| 终结性 | 不适用 | 部署交易所在块在 3 个节点查询地址一致，5 分钟后仍一致 |
| 权限负例 | 有（NotOwner） | 未授权账户部署被节点拒绝（不是 revert），并留日志 |

## 四、给联盟网留的一个改进项

`deployments/<chainId>/Counter.json` 目前没有 `txHash` 与 `blockNumber`：
在 forge script 里 `block.number` 是**模拟上下文**的值（anvil 实测记成 0，已删掉该字段以免误导），
真实 receipt 信息在 `broadcast/Deploy.s.sol/<chainId>/run-latest.json`（含 transactionHash），但该目录被 .gitignore 排除（Foundry 会写敏感值）。

B04 的正确做法（P09 索引器一起做）：部署后由脚本用 `eth_getTransactionReceipt` 补写 `txHash/blockNumber/confirmations` 到部署记录，
这样联盟网交付包里每一份部署记录都能直接对上链上事实，不需要客户再去翻 broadcast 目录。

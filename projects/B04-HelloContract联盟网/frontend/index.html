交易形状与 B04 坑 1 一致：legacy / gasPrice=1 / value=0 / gas=505440， 账户余额 0 → 需要 505440 wei 手续费却付不起。因为 tx-pool-enable-balance-check=false，它会进池： 拿得到 hash，却永远等不到 receipt，还占住该账户的 nonce 0。

② 观测：三个等效信号（跨 3 节点）

不用 txpool_content——它会把全链待处理交易（地址/nonce/金额）暴露到公网 RPC。 改用三个等效信号：in_pool（tx 非 null 且 blockNumber=null）、 receipt（卡单恒 null）、nonce 缺口（pending nonce > latest nonce）。

各节点的卡单信号采样
节点 链高 in_pool receipt nonce latest/pending pending 块含本单

③ 处置：注入最小余额 → 同 nonce 替换

窗口是硬门槛：替换成本 ≤ 注入额 < 卡单成本。 注入太小 → 替换交易自己付不起手续费；注入太大 → 卡单自己变成可执行、直接在原 nonce 入块， 「看起来解锁了」其实测的根本不是替换。

④ 刻意不提供：把「卡单待人工」做成「一键重启节点」

⑤ 证据留痕

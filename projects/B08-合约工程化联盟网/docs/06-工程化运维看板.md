# 06 · 工程化运维看板（B08 前端）

> 补齐项：B08 之前 `frontend/` 是**空目录**——合约层与脚本层都做完了，却没有面向人的页面。
> 这份文档说明看板补了什么、怎么跑、以及它的设计约束（**只读**）。

## 一、为什么 B08 需要一个看板

B08 的产出物天然是"一堆 JSON 报告"（`gas-report.json` / `upgrade-drill.json` / `big-contract.json`），
外加"一串链上状态"（代理现在指向哪个实现、Create2 工厂登记了谁、Merkle 根对不对）。
这些信息在 `deployments/*.json` 里躺着的后果是：

- 对客交付时，**运维方要能自己看到"当前链上是什么状态"**，而不是每次找工程师要一份报告；
- 升级演练后，**"代码可回滚、存储不回滚"这句话要能被当场验证**（快照并排对照）；
- 教学上，**"零 gas 下 Gas 优化的意义是省区块容量"**这句话需要和真实数字并排才立得住。

所以 B08 补了 `frontend/`：**零构建静态页 + 同源 BFF**。

## 二、架构

```text
浏览器 ──同源──▶ BFF（frontend/server.js，node:http + ethers）
                   ├── /                 静态页（index.html / app.js / style.css）
                   ├── /api/state       链状态 + 部署清单 + 三份实测报告
                   ├── /api/chain       chainId / 块高 / 零 gas / 3 节点块哈希一致性
                   ├── /api/vault       Vault 代理：实现槽 / owner / version / 业务槽
                   ├── /api/events      B08 三合约的链上事件（解码 Upgraded/Claimed/Deployed…）
                   ├── /api/create2     Create2 登记与链下双算对账
                   ├── /api/merkle      链上 root() vs 部署记录 merkleRoot
                   └── /rpc             JSON-RPC 同源反代
                          │
                          └──▶ 联盟网 Besu QBFT（127.0.0.1:8551）
```

### 关键设计约束

1. **必须有 BFF，不能纯静态页直连 RPC**
   联盟网 Besu 的 `corsAllowedDomains` 默认是空数组 → 浏览器从页面源直连 8551 会被 CORS 拒
   （403 "CORS Rejected"）。B03 的 `tools/serve-lab.mjs` 用同源反代绕过，B08 走同一条路：
   页面只访问同源 `/api/*` 与 `/rpc`。
2. **看板只读，不持有私钥、不发交易**
   所有写操作（升级 / 空投 / 部署 / 大合约）都在 `scripts/` 里由脚本完成；
   看板的价值是"把链上事实和实测报告并排摆出来"，不是替人签字。
3. **零构建**
   三个静态文件，无 npm 依赖、无打包步骤。`ethers` 只在 BFF 侧用（Node 环境），
   浏览器侧只发 `fetch`。启动就一条命令：`npm run serve`（默认 `127.0.0.1:8808`）。

## 三、页面结构

| 区块 | 内容 | 数据来源 |
|------|------|----------|
| ① 链状态 | 链高 / chainId / gasPrice / baseFee / 零 gas 判定 / 3 节点块哈希一致性 / 区块 gasLimit / Vault 实现槽对齐 | `/api/state`（实时 RPC） |
| ① Vault 明细 | 代理地址、ERC-1967 实现槽、owner、version、slot2 `totalDeposited`、V2 `totalWithdrawn` | `/api/state` |
| ② Gas 双指标 | 四组对照的 naive/opt/saved、占块比例、30M 参考块可装笔数；轻重两批的墙钟延迟与跨块数 | `deployments/gas-report.json` |
| ③ 升级演练 | 变更单、成员签名份数、升级/回滚 tx、before/after/rollback 三快照并排 | `deployments/upgrade-drill.json` |
| ④ 大合约边界 | 24KB / 30KB 两档的字节数、gasUsed、链上代码长度、地址 | `deployments/big-contract.json` |
| ⑤ 地址登记 | Create2 工厂、登记 chainId、部署计数、链上登记地址 vs 事件地址；Merkle 根对账 | `/api/create2`、`/api/merkle` |
| ⑥ 链上工程事件 | B08 三合约的链上事件（解码 `Upgraded` / `Claimed` / `Deployed` / `Initialized` / `OwnershipTransferred`） | `/api/events`（实时 `eth_getLogs`） |

### 一个只有真跑起来才会发现的细节

回滚之后代理的实现是 **V1**，于是 `totalWithdrawn()`（V2 独有字段）在代理上会 **revert**。
看板第一版直接读它 → 整页 500。修法是按 `version()` 分支读，V2 字段读不到就显示
"读不到（当前实现无此字段）"。这恰恰是**"代理升级改变的是 ABI，不是地址"**最好的教学点，
已写进 `lastDepositBlockNote` 字段直接显示在页面上。

## 五、复现

```bash
cd projects/B08-合约工程化联盟网
npm install                      # 只装 ethers
node scripts/run-all.js          # 全量验收（含本看板冒烟）
npm run serve                    # 起看板 → http://127.0.0.1:8808
```

> 前提：联盟网 4 验证者在跑（`shared/consortium-network/scripts/21-up-native.sh`），
> 且 B08 合约已部署（`script/deploy.sh`）。缺任一样，页面会明确显示"未找到 xxx.json，先跑 …"，
> 而不是空白或 500。

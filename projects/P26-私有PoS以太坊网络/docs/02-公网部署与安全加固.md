# 02 · 公网部署与安全加固

> 适用：把私有 PoS 网跑在云主机/客户机房，且允许外部节点加入。
> 命令来源：`ethpandaops/ethereum-package` README「Syncing one enclave from another」，2026-10-14。**本章未在真机验证**，上线前先在测试机走一遍。

## 一、三台机器最小拓扑

```text
主机 A（源）                     主机 B（观察/参与）           主机 C（密钥隔离）
port_publisher.nat_exit_ip=A公网  network: kt-A公网:9090        Web3Signer / 远程签名
el/cl enabled + nginx             （自动 observer，验证者=0）    与节点不同机、不同网段
30303/9000 对等开放               30303/9000 对等开放            只允许 A/B 的固定来源
```

## 二、必做清单（按顺序）

1. **换掉默认助记词**（README §五 红线 1）。
   默认值 `giant issue aisle ... athlete` 是公开在 README 里的——**而且和 anvil 用的是同一串**，
   所以它的 0 号地址 `0x8943545177806ED17B9F23F0a21ee5948eCaa776` 你大概率在 P04–P08 已经见过。
   不替换 = 任何人可花你的预存款，并用同助记词派生的验证者密钥接管链。

   验证派生地址（本机已实测，Foundry 1.7.1）：

   ```bash
   cast wallet address \
     --mnemonic "giant issue aisle success illegal bike spike question tent bar rely arctic volcano long crawl hungry vocal artwork sniff fantasy very lucky have athlete" \
     --mnemonic-index 0
   # → 0x8943545177806ED17B9F23F0a21ee5948eCaa776
   ```

   生成**新**助记词不要用 `cast`（`cast wallet new` 只生成裸私钥/keystore，没有助记词参数）。
   正确做法：用验证者客户端自带的离线生成命令（Lighthouse / Teku 均提供），
   或在离线机器上生成后仅把助记词录入密钥管理——**具体子命令请以你所用客户端的官方文档为准，不要照抄本文**。
   只想换掉"预存款地址"而不涉及验证者时，`cast wallet new` 生成裸私钥即可满足需求。
2. **`nat_exit_ip` 填可路由地址**。README 原文警告：不设则 `enodes.txt` 里全是 docker 内网地址，别的节点连不上。云主机要填**弹性公网 IP**，不是内网卡地址。
3. **防火墙只开 30303 / 9000**（`scripts/30-firewall.sh`）。RPC、CL API、签名接口一律走 SSH 隧道。
4. **9090（nginx 配置分发）限源**。`network-config.tar` 里含 genesis 与节点身份；开放准入的链可以给所有人，**联盟链必须限源**。
5. **持久卷 + 备份**：`persistent: true`、`el_volume_size`、`cl_volume_size` 显式设置。
   A 重启后若节点身份变化，B 必须拆掉重建（README 明确的 gotcha）。
6. **NTP/chrony 强制同步 + 告警**：时钟漂移表现为"莫名漏签"，是最难查的一类故障。
7. **验证者密钥与节点分离**（`keymanager_enabled: true` + 远程签名）。主机被拿下时，攻击者只能让你掉线，不能双签。
8. **监控先于上线**：至少 `beacon_finalized_head`、`validator_monitor_..._attestation_inclusion_delay`、节点 peer 数、磁盘余量。
9. **chainId 登记**：全局唯一，写进交付文档。两个客户内网撞 chainId → 交易可跨网重放（P01 的同一条原理）。
10. **准入与治理写清楚**：谁能加入、谁记账、参数怎么改、出问题谁负责签字。

## 三、加入第二台主机

```bash
# A：起源
kurtosis run --enclave net-a github.com/ethpandaops/ethereum-package --args-file network_params/public-internet.yaml
# 确认 A 已最终化至少 1 个 epoch（或直接用 remote-observer.yaml 里的 --syncmode=full）
RPC=<A 的 EL 转发地址> bash scripts/20-rpc-check.sh

# B：作为 observer 加入
kurtosis run --enclave net-b github.com/ethpandaops/ethereum-package --args-file network_params/remote-observer.yaml
```

已知陷阱（README 原文）：Geth snap-sync 加入"刚起、状态还在长"的 devnet 会卡
`missing trie node ... layer stale` → 目标端 `--syncmode=full`，或等源端最终化 1 个 epoch 后再起。

## 四、合规边界（这一步比技术更容易出事）

| 问题 | 回答要点 |
|------|----------|
| 公网自建链算不算"虚拟货币相关业务"？ | 链本身是基础设施；**只要不发生面向公众的代币发行、兑换、撮合、定价**，与"虚拟货币业务"不是一回事。边界一旦涉及发币即触碰银发〔2021〕237 号 |
| 需要备案吗？ | 面向境内公众提供区块链信息服务 → 《区块链信息服务管理规定》备案义务；纯企业内部/联盟成员间使用另作判断，**签约前请律师出具意见** |
| 数据出境 | 链上数据全球复制，任何个人信息/重要数据上链 = 事实出境。出证只上哈希、脱敏，且评估该链是否含受限数据 |
| 等保/密评 | 公网节点按等保三级设计边界与审计；密钥算法若客户要求国密，则 PoS 以太坊路线不适用（secp256k1/BLS 非国密），要走盟链 + SM2 |
| 谁来记账 | 私有 PoS 的准入是"质押换权"；政企客户要的是"实名 + 授权"。这一点决定你该交付 PoS 还是 Clique（见 `04-选型.md`） |

> 这一节不是法律意见，是**交付前必须逐条过律师**的检查表。

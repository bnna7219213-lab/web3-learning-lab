# 04 · 选型：私有 PoS vs Clique PoA vs 联盟链

> 结论先行：**政企客户 99% 要的不是 PoS 私有网**。这一章的存在是为了让你能明确说出"为什么不用"，而不是"因为我会"。
> 判断依据来自本仓库 商业落地分析报告 §2 政策边界与 §6 商业模型。

## 一、三种准入模型的本质差别

| | 私有 PoS（本章） | Clique PoA（Besu） | 国产/开源联盟链（FISCO BCOS、长安链、蚂蚁链…） |
|--|------------------|--------------------|-----------------------------------------------|
| 谁有权记账 | 质押达标的验证者（**经济权重**） | 被写进 `extraData` 的**实名地址白名单** | 会员 + 证书 + 治理委员会授权 |
| 作恶代价 | 罚没质押 + 掉线 | 身份可追溯，法律与商业关系代价 | 同上 + 监管可穿透 |
| 准入变更 | 需要协议/治理流程 | `discouraged`/`propose` 投票，秒级 | 发证、吊销，有纸质流程 |
| 最终性 | 约 2 epoch（默认约 12.8 分钟） | 出块即近似确定（无 attestation 层） | 通常 PBFT 类，秒级确定性终局 |
| 密码学 | secp256k1 + BLS12-381 | secp256k1 | 多数支持**国密 SM2/SM3/SM4** |
| 运维复杂度 | 高（EL+CL+VC 三进程、keystore、监控） | 低（单客户端） | 中（但厂商包办） |
| 以太坊兼容 | 完全 | 完全（同 EVM） | 部分（需适配层/迁移） |
| 对客话术 | "多机构无中心方的以太坊兼容网" | "几家实名机构共同记账" | "合规基础设施 + 交付兜底" |

## 二、决策树

```text
客户是谁？
├── 政府/国企/银行/链主企业
│   ├── 要求国密、等保、可穿透监管 → 联盟链（不要 PoS，不要 Clique）
│   ├── 只要"几家共同记账 + 以太坊生态" → Besu Clique PoA（运维最省）
│   └── 明确要"最终性可证明 + 无单一运营方" → 私有 PoS，并说清运维成本归谁
├── 集团内部多法人对账（供应链金融/分账）
│   └── Clique 或联盟链：准入=合同关系，比质押更贴合法律事实
├── 研发/CI/教学（需要真实最终性语义）
│   └── 私有 PoS（Kurtosis），或直接用 P02 的 MiniChain 讲原理 + anvil 跑合约
└── 面向公众提供服务
    └── 停：境内公开代币相关 = 红线（银发〔2021〕237 号）。链选型不是这里的问题
```

## 三、什么时候"私有 PoS"是对的答案

1. 客户是**跨境/离岸主体**（香港持牌方），需要以太坊生态且无中心运营方 → PoS 合理。
2. 你要在交付前验证"我们的合约在真实最终性下会不会出问题"（重组、延迟、`finalized` 查询）→ 必须用 PoS 或公共测试网，anvil 测不出来。
3. 多机构**且互不信任到不愿意指定任何一方当发证机构** → PoS 的质押模型比白名单更中立。
4. 需要与公共测试网/主网工具链完全一致（同一套 CL 监控、同一套 keymanager API）。

## 四、什么时候它是错的答案（并要能说清）

| 客户诉求 | 为什么 PoS 不合适 | 该给什么 |
|----------|-------------------|----------|
| "要国密" | BLS/secp256k1 非国密，改造等于换共识 | 联盟链 |
| "要秒级到账" | 2 epoch 最终性 ≈ 12.8 分钟 | Clique / PBFT 类（秒级确定） |
| "我们三家记账，名单我们定" | 质押换权与"合同定名单"不是一回事，反而更贵 | Clique（白名单=合同方） |
| "运维只有两个兼职工程师" | EL+CL+VC+keystore+监控 的运维面太大 | 厂商托管 BaaS 或 Clique |
| "预算一次性，不要年维保" | 私有 PoS 的持续运维成本最高 | 缩小范围：只做存证出证（M4），链用现成的 |

## 五、成本量级（用于报价，非承诺值）

| 项 | 私有 PoS（3 节点） | Clique（3 节点） |
|----|--------------------|------------------|
| 主机 | 3 × 8C16G + 500GB NVMe | 3 × 4C8G + 200GB 可用 |
| 上线人天 | 15–25 | 5–10 |
| 年运维人天 | 30–60（含密钥治理、升级演练、监控值守） | 10–20 |
| 主要风险 | 升级需全体协调、验证者密钥治理 | 白名单地址私钥泄露即等于记账权泄露 |

> 数字为**内部估算口径**，用于与客户谈范围，签约前须按实际机房与 SLA 重算（对齐报告 §8「项目回款慢」「技术债导致交付失败」两条风险）。

## 六、与学习路线的关系

- 本章是 **P22（Geth/Reth 改造）与 P23（应用链）之间的桥梁**：P22 看客户端内部，P26 看怎么把多个客户端组成一张能跑的网。
- 前置真正需要的是 **P02**（自己实现过共识才理解最终性）与 **P11**（多网络 profile）。
- 交付视角的落点在 **P21（监控应急）**：没有 Runbook 与告警的私有网，等于给客户埋雷。

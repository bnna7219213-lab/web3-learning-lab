# 03 · 哈希链与外部锚点：为什么"本地校验通过"仍然不是证据

> 代码：`frontend/lib/hashchain.js`、`frontend/views/chain.js`、`demos/hash-chain.mjs`
> 对应：区块链基础 → 分布式账本 ★★★；P02 MiniChain 的前置

## 机制

```text
block.hash = H(index | timestamp | data | prevHash)
```
每个区块把上一个区块的指纹写进自己的指纹里 → 改任何一处，其后所有指纹都必须重算。

审计做两件独立检查（`auditChain`）：
1. **自洽**：用区块内容重算，是否等于区块里存的 hash；
2. **链接**：本块的 `prevHash` 是否等于上一块存的 hash。

## 三种攻击与检出结果（实测见 `node demos/hash-chain.mjs`）

| 攻击 | 本地审计 | 外部锚点 |
|------|----------|----------|
| ① 只改 data，不动 hash | **失败于第 k 块**（自洽不过） | 一致（链尖未变） |
| ② 改 data 并重算 k 之后全部 hash | **通过**（看起来完全正常） | **不一致 → 识破** |
| ③ 诚实追加 | 通过 | 需要重新锚定才继续一致 |

结论一句话：**哈希链防得住"悄悄改"，防不住"整段重写"；后者要靠锚点。**

## 锚点是什么

`anchor = H(链尖 hash | 链长度)`，把它交给你**控制不了**的地方：

| 锚点形式 | 适用场景 | 成本 |
|----------|----------|------|
| 公链/盟链上写 32 字节 root | 需要对外可自证 | 一笔交易 |
| 公证处/司法鉴定平台定期存证 | 打官司导向 | 按次收费 |
| 客户侧各持一份副本 + 每日互签 | 供应链双方对等 | 运维成本 |
| 自己数据库里的"上一批 root" | 仅内部台账 | 零，但不可对外主张 |

## 与多节点共识的关系

单条链可被持有者整段重算；网络里其他节点各自持有副本，重写者必须让**多数派接受**他的链 → 于是需要共识机制（PoW 算力、PoS 质押、PBFT 背书）。这就是"改历史很贵"的真正来源，而不是哈希本身。

## 工程 checklist（交付时逐条确认）

- [ ] 出证包含：链尖 hash、区块高度、锚点位置（tx hash / 公证编号）
- [ ] 审计方独立于记账方（否则第 ② 类攻击由内部人完成）
- [ ] 定期锚定频率写进 SLA（如每日 00:05 上链 root）
- [ ] 时间来源可信（NTP 被污染会让"时间戳顺序"失去意义）

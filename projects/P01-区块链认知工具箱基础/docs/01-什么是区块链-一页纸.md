# 01 · 什么是区块链（一页纸）

> 用途：给非技术决策人（客户方业务/财务/合规）讲清 5 分钟版本；也是 P01 验收「能讲 what/How/Why」的讲稿。
> 状态：初稿（我的讲法，待你现场讲一次后修订）

## 一句话

区块链是**多方各持一份、按哈希相接、只能追加**的记账副本，它替代的不是数据库，而是「必须先相信某一家」这个前提。

## 三个部件

| 部件 | 作用 | 不这样做会怎样 |
|------|------|----------------|
| 哈希指纹 | 任意内容压成定长值，改一字全变 | 无法判断记录是否被改过 |
| 哈希链接 | 每块写进上一块的指纹 | 可以悄悄改历史而不留痕 |
| 共识/锚点 | 多方对「哪条链算数」达成一致 | 各说各话，仍需一个裁判 |

## 为什么值得花钱

传统系统里，"谁说的算" 由**组织地位**决定（核心企业、平台、银行、我方后台）。区块链把这句话换成** anyone 可复算的规则**：

- 对账不再靠"你导出、我导出、第三方手工核"；
- 争议不再依赖某一方"自证清白"；
- 监管/审计可以独立验证，而不是索取信任。

## 它不解决什么（诚实清单）

1. **不保证输入为真**：设备/人工录入造假，链只保证「录入之后没被改」→ 需要 M2 设备签名与第三方校验。
2. **不保证结论合法**：证据效力仍需公证/司法通道与原始载体。
3. **不省存储与算力**：链上只放哈希与关键金额，其余一律链下。
4. **不替代合同**：链上规则是合同的技术镜像，规则争议仍以合同为准。

## 与 Java/传统后端的对照（讲给工程师听）

| 维度 | 传统后端 | 区块链 |
|------|----------|--------|
| 真相来源 | 主库 + 应用层 | 共识后的唯一状态，每节点可复算 |
| 写操作 | Controller → Service → DAO | 交易（签名）→ 合约函数 → 事件 |
| 权限 | RBAC / JWT | 私钥即身份，`msg.sender` 鉴权 |
| 数据修正 | `UPDATE` / 事务回滚 | 只能追加红冲，历史不可改 |
| 成本 | CPU/内存/磁盘 | Gas：写越频繁、存储越乱越贵 |
| 对外证明 | 报表 + 盖章 | Merkle 出证包，第三方可离线验 |

## 现场讲法（5 分钟）

1. 先讲一次真实扯皮：冷链断链谁负责？（30 秒）
2. 打开 [Demo 2 哈希链](../frontend/index.html)，点 ①②：改数据 → 本地检出；整段重算 → 本地被骗过；锚点 → 识破。（2 分钟）
3. 打开 [Demo 3 Merkle](../frontend/index.html)：13 份单据只上链 32 字节，逐份可证。（1.5 分钟）
4. 收尾：我们卖的不是链，是"改不了、算得出、说得清"这三件事。（30 秒）

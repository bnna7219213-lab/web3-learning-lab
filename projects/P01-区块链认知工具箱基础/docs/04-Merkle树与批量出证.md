# 04 · Merkle 树与批量出证：一个 root 覆盖 N 份单据

> 代码：`frontend/lib/merkle.js`、`frontend/views/merkle.js`、`demos/merkle-proof.mjs`
> 对应：合约进阶 → 架构 → Merkle 树 ★★★（P08/P19 会在 Solidity 里重写一遍）

## 结构

```text
根 root
 ├── 内部节点 ──┬── 内部节点 ──┬── H(leaf0)
 │              │              └── H(leaf1)
 │              └── 内部节点 ── ...
 └── ...
叶子 = H("L|" + 单据原文)，内部 = H("N|" + 左 + 右)
```
- 树高 `⌈log2 N⌉ + 1`；13 份单据 → `13 → 7 → 4 → 2 → 1`（实测）。
- 证明长度 = 树高 − 1，与批次大小成**对数**关系 → 批次越大越划算。

## 出证与验证

出证包（`buildProofPackage`）：`{ index, data, leafHash, root, proof[{hash, position}], total }`。
验证 = 从叶子沿 proof 爬到根，比对链上 root（`computeRootFromProof`）——**第三方无需访问你的数据库**。

实测（`node demos/merkle-proof.mjs`）：把第 7 份金额改成 999999 后复算根 `e8fe7d11…` ≠ 链上根 `9a70e0ab…` → 拒绝。

## 成本对比（1000 份单据）

| 方案 | 链上写入 | 备注 |
|------|----------|------|
| 逐份上链 | 1000 笔 × 约 2.1 万–5 万 Gas | 成本、吞吐、隐私全输 |
| Merkle 批量 | 1 笔 32 字节 root | 逐份可证，验证 Gas ≈ 树高 × 一次哈希 |
| 纯链下台账 | 0 | 不可对外主张（见 03 篇） |

## 三个必须知道的坑

1. **奇数节点复制末尾**（教学做法）会让 `["A","B","C"]` 与 `["A","B","C","C"]` 撞同一个 root —— 单测已把这条固定为已知弱点。生产用**索引哈希**（把 leaf index 进哈希）或 **Merkle Mountain Range**、或固定深度 + 空叶子哨兵值。
2. **域分隔**：叶子与内部节点必须不同前缀，否则一棵树的内部节点可被冒充成另一棵的叶子。
3. **可 malleability**：proof 里的 `position` 若由验证方"排序后拼接"（sort-pair 方案）会引入歧义，需与合约实现一致。

## 复用场景（同一形状，不同业务）

| 场景 | 叶子是什么 | root 写在哪 |
|------|------------|-------------|
| M4 批量存证 | 单据指纹 | 存证合约 / 每日锚定交易 |
| M1 分账批次 | `{收款人, 金额}` 指纹 | 结算批次 root，逐笔 claim 时验证 |
| 批量发放/领取 | `{地址, 额度}` | 合约 `verifyProof` 后一次性领取 |
| 快照治理 | `{账户, 权重}` | 提案绑定某个 root，防历史篡改 |

# P09 设计：表设计 / 重组协议 / 游标分页 / REST 契约

## 1. 表设计（SQLite 落地 + PostgreSQL DDL 对照）

六张表分三类：**事实表**（blocks/txs/logs，只追加）、**派生表**（assets/holders，可重算）、**游标表**（单行）。

| 表 | 主键 | 语义 | 回滚时 |
|----|------|------|--------|
| blocks | number | 高度/哈希/父哈希/时间戳 | 删 `> N` |
| txs | hash（+`UNIQUE(blockHash, txIndex)`） | 交易逐字段（复用 P03 解析口径） | 删 `> N` |
| logs | 自增 id + `UNIQUE(blockHash, logIndex)` | 原始 topics/data + 解码 + 抽平过滤列 | 删 `> N` |
| assets | (contract, tokenId) | 派生：721 当前持有人 | **重放重建** |
| holders | (contract, address) | 派生：持仓计数 | **重放重建** |
| cursor | id=1 单行 | lastBlock/lastHash/chainKey | 退回 N |

**幂等写入**：三个事实表都用链上不可变标识做冲突键，`INSERT ... ON CONFLICT DO UPDATE`。
同一段区间扫 100 遍 = 100 次同值覆盖，行数不变（验收 E 组实测）。

**PostgreSQL DDL 对照**（教学口径；生产直接用 PG 时的映射）：

```sql
-- 与 migrations/001-init.sql 一一对应，差异只有类型与索引语法
CREATE TABLE blocks (
  number     BIGINT PRIMARY KEY,
  hash       BYTEA NOT NULL,          -- TEXT 0x-hex 亦可，BYTEA 省一半空间
  parent_hash BYTEA NOT NULL,
  timestamp  BIGINT NOT NULL,
  tx_count   INT NOT NULL DEFAULT 0,
  indexed_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE TABLE txs (
  hash BYTEA PRIMARY KEY,
  block_number BIGINT NOT NULL REFERENCES blocks(number) ON DELETE CASCADE,
  block_hash BYTEA NOT NULL,
  tx_index INT NOT NULL,
  from_addr BYTEA NOT NULL,
  to_addr BYTEA,
  value NUMERIC(78,0) NOT NULL,      -- uint256 用 NUMERIC，别用 BIGINT
  input BYTEA NOT NULL,
  selector BYTEA,
  method TEXT,
  status SMALLINT,
  gas_used NUMERIC(78,0),
  UNIQUE (block_hash, tx_index)
);
CREATE TABLE logs (
  id BIGSERIAL PRIMARY KEY,
  block_number BIGINT NOT NULL REFERENCES blocks(number) ON DELETE CASCADE,
  block_hash BYTEA NOT NULL,
  tx_hash BYTEA NOT NULL,
  log_index INT NOT NULL,
  address BYTEA NOT NULL,
  topic0 BYTEA,
  topics JSONB NOT NULL,
  data BYTEA NOT NULL,
  event_name TEXT,
  decoded JSONB,
  from_addr BYTEA, to_addr BYTEA, token_id NUMERIC(78,0), batch NUMERIC(78,0),
  UNIQUE (block_hash, log_index)
);
CREATE INDEX ON logs(block_number);
CREATE INDEX ON logs(address);
CREATE INDEX ON logs(event_name);
CREATE INDEX ON logs(batch);          -- B09 的主力筛选列
CREATE INDEX ON logs(from_addr);
CREATE INDEX ON logs(to_addr);
-- assets / holders 同构；cursor 可换成 Redis 单键
```

PG 特有注意：①回滚的三张表删除要包事务，`ON DELETE CASCADE` 让 logs/txs 跟 blocks 一起删；
②`NUMERIC(78,0)` 存 uint256（BIGINT 会溢出）；③JSONB 的 `decoded` 可直接 `decoded->>'tokenId'` 查询，
但高频筛选列（batch/tokenId）仍建议抽平成实体列——**JSONB 查得动 ≠ 查得快**。

## 2. 区块重组协议（三步，scanner.js）

```
syncOnce():
  head = eth_blockNumber();  safe = head - confirmations
  ① 链回卷：cursor.lastBlock > head            → rollbackTo(公共祖先)
  ② 分叉：  cursor 块的 hash ≠ 链上同高度 hash   → findCommonAncestor() → rollbackTo(祖先)
  ③ 前进：  [cursor+1, safe] 分片拉块 + eth_getLogs（address 过滤）→ 幂等写入
```

- **findCommonAncestor(n)**：从 n 往下逐块比对本地 hash 与 `eth_getBlockByNumber`，第一个一致的高度即祖先；
  链上高度消失（回卷）返回 `i-1`；全不一致返回 `startBlock-1`。
- **rollbackTo(N)**：同事务删 `blocks/txs/logs` 中 `> N` 的行，游标退回 N.hash，然后 **rebuildAssets()**
  从 logs 全量重放派生态（721：mint/transfer/burn；1155：数量语义单列计数）。
- **confirmations 深度**：只扫 `safe`，不追头。anvil 交易秒出块时深度=2 就得「再挖 2 块」才可见（settle）；
  QBFT 单块终结的联盟链可设 0（见 B09 差异矩阵）。
- **实测**：anvil `evm_snapshot` → 2 mint → `evm_revert` → 换 3 mint → 索引器检测 `kind=fork`、
  rolledBackTo=快照高度，旧分叉事件/交易清零、新分叉重放（验收 C 组 10 项断言）。

## 3. 幂等与游标分页

- **幂等**：冲突键 = 链上不可变标识。**不要**用「块高」当 logs 主键——重组后同高度换块会插不进去。
- **游标分页**：`ORDER BY (blockNumber, index) DESC` + `WHERE (blockNumber, index) < (cursor)`，
  返回 `nextCursor = "blockNumber:index"`。链上数据只追加 ⇒ keyset 分页天然稳定：
  翻页途中新出的块只会出现在列表**头部**，不会把已翻过的行挤到下一页（验收 B 组实测）。
  对照：`OFFSET` 分页在追加型数据上会「漏行/重行」，是链上数据平台最常见的自伤。

## 4. REST 契约（BFF，Java 侧对接照抄这张表）

| 方法 | 路径 | 参数 | 返回 |
|------|------|------|------|
| GET | `/api/health` | — | `{ok, head, cursor, chainKey}` |
| GET | `/api/stats` | — | `{data:{blocks,txs,logs,assets,holders,events[]}}` |
| GET | `/api/logs` | `address,eventName,batch,tokenId,fromAddr,toAddr,blockFrom,blockTo,q,after,limit` | `{items[],nextCursor}` |
| GET | `/api/txs` | `fromAddr,toAddr,blockFrom,after,limit` | `{items[],nextCursor}` |
| GET | `/api/holders` | `contract,limit` | `{data[]}` |
| GET | `/api/assets` | `contract,owner,limit` | `{data[]}` |
| POST | `/admin/sync` | 头 `X-API-Key` | 触发一次同步 |
| POST | `/admin/rollback?to=N` | 头 `X-API-Key` | 回滚到 N（演练/修复用） |

- 所有响应带 `x-response-ms`（延迟观测，验收 D 组直接读它）。
- 管理口与读口分离鉴权：读口公开（内网看板），管理口必须 `X-API-Key`（验收 F 组断言 401/200）。
- **GraphQL 可替换性**：`db.js` 的 `queryLogs/queryTxs` 就是 resolver 的全部数据来源——
  换 GraphQL 时 schema 的 `logs(filter, cursor)` 直接映射这两个函数，不必重写查询层。

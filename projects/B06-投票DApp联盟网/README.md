# B06 · 审批/投票 DApp（联盟网）

> 状态：未开始 ｜ 对应主线：[P06](../P06-投票DApp基础/README.md) ｜ 网络底座：[shared/consortium-network](../../shared/consortium-network/README.md) ｜ 更新：2026-10-14
> 一句话目标：把投票 DApp 升级为**多成员审批流**：不同成员用各自账户签名、双人复核、前端可切换成员身份。

## 与 P06 的关系

**功能实现一致，环境语义不同。**P06 的全部知识点在本分支都要做一遍，本 README 只记录**差异与新增验收**；
共性差异见 [差异矩阵](../../shared/consortium-network/docs/04-差异矩阵-P03-P08-vs-B03-B08.md)。

| 维度 | P06（公链/anvil） | B06（联盟 QBFT） |
|------|------------------------|----------------------|
| 交互主体 | 单个学习钱包 | **多成员账户**，每成员独立身份与权限 |
| 钱包 | MetaMask | MetaMask 在零 gas 链上会异常 → 用后端代签或 viem 显式 maxFeePerGas=0 |
| 业务语义 | 投票 | **双人复核/授权**（M5 补贴直达的核心流程原型） |
| 新增验收 | — | 未授权成员操作被拒且留痕；两成员并发操作 nonce 不串 |

## 知识点

- [ ] 多账户 nonce 管理器（按 address 串行化）
- [ ] viem 直连联盟网 RPC（绕开钱包对零 gas 链的校验问题）
- [ ] 审批状态机：提案 → 复核 → 生效延迟 → 执行
- [ ] 成员身份与链上地址映射（对应 M4 企业可信档案）
- [ ] 事件驱动的前端刷新与索引延迟处理

## 技术栈

- Next.js/React + viem（不依赖 MetaMask 注入）
- Solidity 审批合约
- 数据：联盟网事件 + 内网索引（B09 前用轻量轮询）

## 验收

**分支共用四条增量**（B03–B08 一律适用）：

- [ ] 多成员：≥2 个成员账户各自发交易，nonce 互不干扰
- [ ] 零 gas：`eth_gasPrice == 0` 且 `baseFeePerGas == 0`，交易确实入账
- [ ] 终结性：交易所在块在 3 个节点查询一致，5 分钟后仍一致
- [ ] 权限负例：未授权账户/节点被拒且留下可审计记录

**本分支特有**：

- [ ] 2 个成员账户并发各发 10 笔，全部成功且顺序正确
- [ ] 未授权成员发起审批 → 前端可读的拒绝原因 + 链上留痕
- [ ] 提案到执行含生效延迟，可演示「撤销窗口」

- [ ] README 可按步骤复现（含联盟网准备步骤）
- [ ] 去代币化检查表通过（涉及对外交付时）

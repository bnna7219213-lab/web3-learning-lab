# B05 合规边界：本代币（LAB）不是虚拟货币的三条依据

> 结论先行：LabToken 是**联盟内部记账单位**，不构成虚拟货币或金融资产。三条依据如下，
> 每条都给出「要求 → 技术/制度落点 → 可核验方式」，对客交付时按此口径解释。

## 依据一：用途限定——不具有流通与支付功能

| 项 | 内容 |
|----|------|
| 要求 | 虚拟货币的核心特征是可对外流通、可支付、可二级交易；LAB 一项都没有 |
| 制度落点 | 《成员协议》限定 LAB 仅用于联盟内服务量记账与结算折算，**禁止对外转让、禁止兑换法币、禁止二级市场报价** |
| 技术落点 | 无 DEX/市场合约对接；合约无价格字段、无撮合接口；发行与销毁只走 MINTER 角色 |
| 可核验 | 链上可查：持有地址全部为成员白名单内账户（对账脚本断言「holder ⊆ 成员集合」）；任何外部地址出现即审计告警 |

## 依据二：发行受控——不是任意主体可发的「币」

| 项 | 内容 |
|----|------|
| 要求 | 虚拟货币往往无发行上限或任意增发；LAB 的发行是**受治理的内部授信** |
| 制度落点 | 发行权归运营方（多签演进路线：单签 → 多签 → 时间锁，见 README 知识点）；每次发行对应真实服务合同 |
| 技术落点 | `CAP`（发行上限）构造时固化不可改；`MINTER_ROLE` 与 `DEFAULT_ADMIN_ROLE` 分离；`test/RoleMatrix.t.sol` 8 条负例证明未授权铸造/改角色全部 revert |
| 可核验 | 链上 `totalSupply ≤ CAP` 恒成立（invariant 测试）；角色变更打 `RoleGranted/RoleRevoked` 事件可审计 |

## 依据三：无投机属性——价值锚定服务量，不锚定价格

| 项 | 内容 |
|----|------|
| 要求 | 虚拟货币具有价格发现与投机属性；LAB 没有 |
| 制度落点 | 1 LAB = 合同约定的 1 单位服务量记账口径（如 1 次核销），**不与任何货币/资产建立兑换关系**；对账按服务量而非市值 |
| 技术落点 | 无预言机价格接入；`quoteProRata` 等视图只做按持仓比例的分摊算术（对账/清算用），不产生价格 |
| 可核验 | 对账口径与舍入方向写进测试（`Invariant.t.sol`/`LabToken.t.sol`）：**向下取整、dust 留池、不超发**——联盟各方用同一算式复核 |

## 分层执行（诚实说明技术边界）

- 合约层（P05 同源码）：角色治理 + 发行上限 + 事件留痕；
- 组织层：成员协议约束转让范围（上表依据一）；
- 审计层：100 笔转账对账（`scripts/01-acceptance.mjs` B 组）证明余额与台账零差异、
  事件可重放重建台账——**可审计性是「内部记账单位」的执行抓手**。
- 若客户要求**合约级**封锁对外转让（白名单外拒转），方案是把 B07 的 `_update` 成员策略移植到 LabToken
  （一行策略 + 双路留痕），属定制交付项；教学基座保持与 P05 同源码，便于对照「同一份合约在不同治理口径下的差异」。

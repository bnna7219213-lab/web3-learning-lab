# 01 · NFT 市场：租期、版税、撮合与合规开关

> 配套：`src/{LabNFT,LabEditions,NFTMarket}.sol` · `frontend/src/App.jsx` · 日期：2026-11-11
> 35 项测试全绿；LabNFT/LabEditions 覆盖率 100%，NFTMarket 91.4% 行。

## 1. EIP-4907：owner 与 user 是两种产权

- `owner` = 处分权（卖/烧/设租约）；`user` = 限期使用权（租赁场景：游戏账号、设备时段）。
- `setUser` 只允许 owner 或 approved 操作者；`userOf` 在 `expires < block.timestamp` 时**自动返回 0**——
  到期不需要任何人发交易"收回"，权限随时间失效（`test_UserExpiresAutomatically`，含 expires 当刻边界）。
- **转让/burn 清空租约**（`_update` 钩子）：新 owner 不应被旧租约占用。E2E 里挂单托管→成交→下架
  每次转让都伴随 `UpdateUser(token, 0x0, 0)` 事件，链上可直接观察。
- 与 Java 对照：owner≈所有权登记，user≈带 TTL 的授权令牌；区别是 TTL 由共识时间执行，无需清理任务。

## 2. ERC2981 版税：是建议，不是强制

- `royaltyInfo(tokenId, salePrice)` 只是**报价接口**：不实现它的 NFT 版税为 0；实现它但市场不读，也收不到。
  本版税在**市场合约成交路径**里强制分配（先版税后卖家），但绕过市场的私下转账收不到——这就是局限。
- 防御：报价超过成交价时按 0 处理（`test_RoyaltyOverPriceDefended`），异常 NFT 不能掏空买家。
- fuzz 钉死守恒：`卖家所得 + 版税 == 成交价`（500 轮）。

## 3. 两条撮合路径：托管挂单 vs 签名订单

| | 托管挂单 list/buy/cancel | 签名订单 fillOrder |
|--|--------------------------|---------------------|
| NFT 位置 | 挂单即进市场合约（escrow） | 留在卖家钱包，成交才转 |
| 卖家成本 | 一笔 list tx + 授权 | 零 tx（链下签名） |
| 买家风险 | 低（币已托管） | 卖家可在成交前转走币 → fill revert |
| 取消 | cancel tx | 不填即作废（deadline/nonce） |
| 重放防护 | active 标志 | nonce 单次 + deadline + EIP-712 域 |
| 适用 | 公开挂单簿 | 链下撮合/OTC/聚合器 |

签名订单 = EIP-712 `SellOrder(seller,nft,tokenId,amount,price,nonce,deadline)`；
改价/代签/跨域/重放/过期五类负例全部有测试。E2E 用 anvil 的 `eth_signTypedData_v4`
经演示钱包 shim 签名（MetaMask 路径同接口），买家填单成交，`OrderFilled` 入事件流。

## 4. 转账安全与托管守恒

- 一切 NFT 移动走 `safeTransferFrom`；市场实现 721/1155 接收钩子（否则托管进不来——实测踩到）。
- `buy/fillOrder/list/cancel` 全 `nonReentrant`；重入攻击者合约在接收回调里再买同一单 → 整笔回滚（测试）。
- 付款用 `Address.sendValue`（失败即 revert），CEI：先置 active=false 再付钱转币。
- invariant：`市场持有 721 数 == 活跃挂单数`、`nextId 不变`（市场只流转不铸造），64×32 轮。
- 1155 按 amount 托管/成交；fuzz 钉死 `买家份数 + 卖家份数 == 原总量`。

## 5. 合规开关：二级市场入口默认关闭

`tradingEnabled` 默认 **false**：list/buy/fillOrder 全部 revert `TradingDisabled`。
开启是 admin 的显式治理动作（前端 admin 面板按钮 / cast）。**cancel 不受开关限制**——
入口关闭时卖家仍须能取回托管资产（`test_CancelStillWorksWhenDisabled`）。
部署记录里落 `tradingEnabled` 字段，交付时可自证默认状态。

## 6. IPFS 元数据与哈希锚定

- 本机 kubo（offline daemon，API 5001 / 网关 8088）；`scripts/pin-metadata.mjs` 与前端铸造都走
  `/api/v0/add?pin=true&cid-version=1`；`tokenURI = ipfs://<CIDv1>`。
- CID 即内容哈希：改一个字节 CID 变 → 链上锚的是**内容**不是位置；pin 脚本读回逐字节比对（IDENTICAL）。
- 前端把 `ipfs://` 替换为本地网关读元数据与图片；离线可复跑，不依赖公网 gateway/Pinata。
- 生产对照：客户 OSS + 哈希上链是同构替代（差异矩阵 B07 行）。

## 7. 前端实测踩坑（已修）

1. **挂单前未授权**：list 要求 market 被 approve；前端改为检测 `isApprovedForAll` 不足先补授权，
   同 sender nonce 顺序保证先授权后挂单（MetaMask 下表现为连续两次确认）。
2. **useReadContracts 的 tuple 返回是数组**：按对象 spread 会丢字段（挂单板空白的根因）。
3. 演示钱包 shim 补 `eth_signTypedData_v4` 转发 anvil——签名订单路径零私钥可跑。

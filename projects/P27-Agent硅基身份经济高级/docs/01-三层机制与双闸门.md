# 01 · 三层机制与双闸门：Agent 硅基身份经济的设计

> P27 的核心命题：**给链上与支付流程中的 Agent 一个可认定、可积累、可授权、可问责的经济身份**。
> 机制参考属主仓库 nexalink 的 CPHS 实名 Agent 支付嵌入机制（`contracts/cphs/`，docs/15），
> 本实验将其剥离为可独立复跑的学习项目，差异与加固见 [02-nexalink对照-CPHS.md](./02-nexalink对照-CPHS.md)。

## 1. 为什么 Agent 需要「身份经济」

一个能自主发起链上支付的 Agent，绕不开四个问题：

| 问题 | 没有答案时的后果 | 本项目的落点 |
|------|------------------|--------------|
| 谁可以被认定？ | 匿名地址女巫刷量，支付能力无从分级 | LabID：链下核验 → soulbound 身份 |
| 能力从哪里来？ | 一次性授权=永久全权，无法渐进信任 | SignalRegistry：信号积累 → reputation → tier |
| 什么情况下可付？ | Agent 滥付 / 被诱导支付 | PaymentMandate：四道锁 + 条件哈希锚定 |
| 出了事怎么问责？ | 决策黑箱，无法审计 | reasonRef → 链下 agent_run 决策日志 |

「硅基」不是特权标签：`isAgent=true` 的身份与碳基身份走**同一套协议、同一张 tier 表**——
T0 的 Agent 一样不能代付，T3 的 Agent 与 T3 的人类上限完全相同。不豁免、不歧视。

## 2. 三层架构

```text
【认证】谁可以被认定
  链下 KYC 核验（PII 不上链）→ LabID 铸造（soulbound，人类/Agent 同构）
  → 信号积累（行为/生理/跨平台/Agent 指纹）→ reputation → tier T0–T3

【授权】在什么情况下可付
  PaymentMandate（用户一次性签署）锚定：收款方 + 单笔/累计上限 + 有效期 + 条件哈希
  （条件语义链下解释，链上锚定留痕）

【执行】省去用户操作的边界
  PaymentAgent.pay() 在 min(mandate 上限, tier 上限) 内免用户操作执行
  超出任何一边 → 回到用户签名（硬边界，不可省）
```

### 2.1 身份层（LabID.sol）

- **soulbound**：`_update` 单漏斗拦截转让。可转让的身份会被批量注册套利。
- **一地址一 ID**：`idOf(addr)` 唯一，重复铸造硬拒绝，失败不消耗 ID。
- **PII 永不上链**：链上只有 `kycCommit = keccak256(材料摘要+盐)`，可事后证伪、不可反推原文。
- **tier 由声誉推导**：rep ≥ 100/500/2000 → T1/T2/T3，不是人工指定；负 delta 钳制到 0，降级即时生效。
- **写口唯一**：只有 `SIGNAL_ROLE`（= SignalRegistry）能写 reputation。

### 2.2 信号层（SignalRegistry.sol）

三段流程：

1. **承诺**：provider 提交 `commit(subject, domain, sigHash, kind, ts)`——原始信号向量留链下。
2. **阈值确认**：验证者对 `keccak256("LabSignal-Confirm", cid, subject, sigHash, kind, ts)`
   做 EIP-191 签名，默认 **3/5** 达标自动入账。
3. **入账**：`addReputation(subject, weight)` → tier 提升；跨入 T1+ 发 `ResonanceUnlocked` 钩子。

信号权重表（可治理调整，钳制在 int256.max 内）：

| kind | 语义 | 权重 |
|:----:|------|:----:|
| 0 Behavioral | 操作行为（支付行为习惯等） | 10 |
| 1 Physiological | 生物/生理信号（碳基主体） | 30 |
| 2 CrossPlatform | 跨平台身份一致性 | 40 |
| 3 AgentFingerprint | AI 智能体指纹（模型/运行时行为签名） | 20 |

防女巫与防重放：

- 无 LabID 不能提交信号（匿名地址刷不了声誉）
- 去重键 `keccak(subject, domain, sigHash)`——同一信号只能提交一次，跨域算不同信号
- 新鲜度窗口 24h + 时钟容差 1h（旧信号不能重放，未来信号拒绝）
- 同一验证者对同一承诺只能签一次；非验证者签名 `NotVerifier`

### 2.3 支付层（PaymentAgent.sol）

**双闸门（缺一不可）**：

```text
单笔上限 = min(mandate.perTxLimit, tierPerTxLimit[payer.tier])
累计上限 = min(mandate.totalLimit, tierTotalLimit[payer.tier])
```

| tier | reputation | 单笔上限 | 单凭证累计上限 |
|:----:|:----------:|:--------:|:--------------:|
| T0 | 0–99 | **0（不能代付）** | 0 |
| T1 | 100–499 | 100 | 300 |
| T2 | 500–1999 | 1,000 | 3,000 |
| T3 | ≥2000 | 10,000 | 30,000 |

（LabUSD 6 位小数；上限表可治理调整。）

**PaymentMandate 四道锁**：限额（单笔+累计）/ 限对象（payee 创建后不可改）/
限时（validUntil 过期即失效）/ 一次性登记（有效边界哈希去重）。

关键机制：

- **创建即钳制**：申请上限被钳制到 tier 上限——授权不能超越身份等级；T0 连授权都开不出（`TierTooLow`）。
- **执行时点二次校验**：声誉是动态的。身份降级 → 单笔**与累计**额度同时收紧
  （历史支出不动，剩余额度即时归零）。这是 P27 相对参考实现的加固点，见 docs/02 §2。
- **调用者两类**：`AGENT_ROLE`（平台运行时）或 `payer` 本人（账户自调用）；其余 `UnauthorizedPayer`。
- **撤销/过期即时生效**：payer 本人或治理可撤销。

### 2.4 条件语义：「什么情况下」怎么处理

`mandate.conditionHash` 把触发条件（账单到期 / 库存低于阈值 / 收成信号确认…）的语义哈希锚定上链。
**链上不解释条件本身**——条件判定是 Agent 运行时的职责。链上保证的是：

1. 每笔执行记录都绑定它声称满足的条件哈希（不可事后改口）
2. `reasonRef` 指向链下决策日志（`scripts/agent-demo.mjs` 的 `agent_run` 全程留痕）
3. 金额/对象/时间永远被 mandate 硬边界约束——**条件判错，损失有界**

Agent 运行时演示（`data/agent-runs/<runId>.json`）的六步留痕：
`identity-check → mandate-created → read-boundary → boundary-check → execute → reconcile`；
超界时 `boundary-check` 后直接 `escalate`，**零交易**回到用户签名。

## 3. 攻击面与缓解

| 攻击 | 缓解 | 钉死它的测试 |
|------|------|--------------|
| 批量注册套利 / 身份买卖 | soulbound + 一地址一 ID + 仅 REGISTRAR 铸造 | LabID.t.sol ×3 |
| 匿名女巫刷声誉 | 无 LabID 不能 commit | SignalRegistry.t.sol |
| 旧信号 / 跨域重放 | 去重键 + 24h 新鲜度 + 未来信号拒绝 | 同上 ×3 |
| 验证者不足阈值入账 | 3/5 计数，2 签不入账 | 同上 |
| 验证者重复签名 / 非验证者签名 | AlreadySigned / NotVerifier | 同上 |
| 篡改信号内容后重签 | 合约按链上承诺重算 digest，recover 出随机地址 | TamperedDigest |
| 授权超越身份等级 | 创建即钳制 + T0 拒绝 | PaymentAgent.t.sol |
| Agent 超限额 / 超对象 / 超时效支付 | 四道锁 + 双闸门 | 同上 ×6 |
| 身份降级后继续大额支付 | 执行时点二次校验（单笔+累计） | TierDowngrade ×2 |
| 无关地址冒用授权 | UnauthorizedPayer / UnauthorizedRevoker | 同上 |
| 决策黑箱无法问责 | conditionHash + reasonRef 双锚定 | acceptance E01/E04 |

## 4. 边界与后续接口（本期不做）

- **AA × 会话密钥集成**：nexalink 已落地（账户层选择器白名单 + Paymaster 补贴隔离），
  P27 只做合约层 + Node 运行时；联盟网版（B 线）可作为后续章节。
- **EIP-712 用户直签 mandate**：当前由 payer 地址登记（approve 是真实同意锚点），可升级为用户自签。
- **EIP-1271 合约签名验证者**：当前验证者为 EOA 多签，接口处可扩展。
- **罚没（slashing）治理**：`addReputation` 支持负 delta，但 SignalRegistry 只加正分；
  降级路径在测试中由持 SIGNAL_ROLE 的治理主体演练，生产化需要独立的罚没治理合约。
- **GameFi 共鸣**：`ResonanceUnlocked` 事件钩子已留，上层应用自行监听。

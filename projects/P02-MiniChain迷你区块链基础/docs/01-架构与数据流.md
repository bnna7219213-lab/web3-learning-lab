# P02 · 架构与数据流

## 分层

```text
src/crypto.js   SHA-256 / ECDSA P-256 签名验签 / 地址派生 / JWK 导入导出
     ↑
src/tx.js       交易结构、规范化 preimage、签名检查、状态迁移（nonce/余额/手续费）
     ↑
src/block.js    Merkle root、区块哈希、PoW 搜索 / PoS 轮值、区块自洽校验
     ↑
src/chain.js    整链重放、权重计算、分叉点定位、重组计划、确认数
     ↑
src/mempool.js  交易池：形/签名/状态预检、同 nonce 高费替换、回炉
     ↑
src/node.js     HTTP 服务（P2P gossip + 查询 API）+ 出块循环 + 启动追赶
     ↑
bin/            network.mjs（起网）· experiments.mjs（四条验收实验）
frontend/       节点面板（与节点共用 src/crypto.js、src/tx.js）
```

## 一笔转账的生命周期

```text
钱包签名(createTx)
  → POST /tx 到任一节点
      ├─ checkTx：字段 → 地址与公钥匹配 → 验签
      ├─ precheck：nonce 连续、余额够付 value+fee
      └─ 进池并 gossip 给 peers
  → 轮到出块的节点 select(费用优先) → 状态副本预演过滤不可执行交易
  → sealBlock：PoW 搜 nonce 或 PoS 校验轮值
  → tryAppend：结构校验 + 逐笔 applyTx（在状态副本上）→ 成功才 append
  → broadcast 区块；邻居接不上就拉对方整条链比权重（adoptIfHeavier）
  → 邻居重放后账本一致；交易从其 mempool 移除
```

## 关键不变式（都有对应单测）

| 不变式 | 位置 |
|--------|------|
| 区块 hash 唯一由内容决定（改交易/改余额表必变） | `block.test.mjs` |
| `txIds` 与 `merkleRoot` 必须能由交易列表重算出来 | `block.test.mjs` |
| 只有 `prevHash` 指向本地链尖的块才能直接追加 | `chain.test.mjs`「断链」 |
| 权重严格更大才切换链；等重不切（防抖动） | `chain.test.mjs`「等重不切」 |
| 被丢弃区块的交易必须回到交易池，且不能二次入账 | `chain.test.mjs`「重组」+ 实验 3 |
| 余额、nonce 在任何节点重放后完全一致 | `network.test.mjs` 实验 1 |
| 非轮值人出块一律为 null / 被 validateBlock 拒绝 | `block.test.mjs`「PoS」 |

## 状态一致性怎么做到的

节点不保存"当前账本"作为真相，只保存链；账本永远是 `replayChain(chain)` 的结果。
所以重组、追赶、重启三条路径都收敛到同一个状态——代价是链长后重放变慢（真实节点用快照解决，见「设计取舍」）。

# P02 · 设计取舍与已知限制

> 这一页是本项目最有价值的部分：**每一条"简化"都对应真实链的一个机制**，写清楚才不会把玩具当生产。

| # | 我们的做法 | 真实链的做法 | 为什么先这样 | 什么时候必须换 |
|---|------------|--------------|--------------|----------------|
| 1 | ECDSA **P-256**，交易里带公钥 | secp256k1 + keccak256 + **可恢复签名**（从 sig 反推 pubkey，省字节） | 浏览器/Node 的 Web Crypto 没有 secp256k1，零依赖优先 | 要和 MetaMask/真实地址互通时（P03/P04 起用 viem/Foundry） |
| 2 | 地址 = `sha256(pubkey)` 前 40 位 | `keccak256(pubkey)` 后 20 字节 | 教学等价：都是"公钥的单向压缩" | 任何需要校验和(EIP-55)或真实地址的场景 |
| 3 | 权重 = Σ 2^difficulty（PoS 记 1） | 累计总难度（TD），PoS 用最终性小工具 | 只要能让"更贵"胜过"更长"就够 | 做 51% 攻击成本测算时 |
| 4 | 账本 = 每次全量重放 | 状态树（MPT）+ 快照 + 归档节点 | 链短，重放 <10ms，逻辑最简 | 链过万块 / 需要历史查询时（P09 索引器） |
| 5 | Merkle：奇数复制末尾 | 索引哈希 / Merkle Mountain Range | 与 P01 保持同一实现，便于对照；弱点已在 P01 单测固化 | 出证材料要对外（M4）时必须换 |
| 6 | 轮值 PoS：`validators[h % n]` | 加权质押 + VRF 选主 + 罚没 + 最终性检查点 | 一眼看懂"谁是记账人" | 讨论作恶成本、无活性惩罚时（P23/P24） |
| 7 | 无质押、无罚没 | 押金 + slashing | 学习链没有经济 | 讲 M2 设备奖励滥用时（对应 lainchain 的罚没设计） |
| 8 | 交易只有转账 | 合约调用、事件、Gas、存储 | 先分清"状态迁移"与"业务逻辑" | P04 起换成真 EVM |
| 9 | 手续费恒归本块 proposer | 拍卖/最小费/EIP-1559 燃烧 | 让「出块有收益」这件事可见 | 讨论 MEV 与费用市场时 |
| 10 | HTTP 轮询 + 广播做 P2P | libp2p/RLPx、gossip、区块头先行同步 | 少一层依赖，链路可视化 | 节点 >20 或要跨网时 |
| 11 | 创世余额表进区块哈希，但**不**做状态根承诺 | 创世 stateRoot + 每块 stateRoot | 已能抓住"偷改初始有钱人"（有单测） | 需要 SPV 式轻客户端验证时 |
| 12 | 只绑 127.0.0.1，CORS 只放行本机来源 | 公链 RPC 有鉴权/限量/WAF | 本地实验 | 任何对外部署前（P21 运维） |

## 明确不做的

- **不实现钱包助记词/BIP-32 派生**：P03 用 MetaMask 做，避免两套半成品。
- **不做持久化**：进程退出即丢链。要长期跑就接 P09 的索引器落库。
- **不做防女巫/防合谋**：PoS 轮值假设验证人集合可信且已实名——这正是**联盟链**的真实假设，也是 M2/M4 交付时的合规基础。

## 已知 bug 面（诚实清单，后续项目会撞上）

1. 交易池按 `from:nonce` 只留一条，**不支持**排队多条后续 nonce。
2. 重组后回炉的交易若已被别的高费替换，可能永久滞留池中（真实节点有 TTL 与淘汰）。
3. 广播是同步等待（`Promise.allSettled`），节点多时会拖慢出块；应改成异步队列。
4. 时间戳用 `Date.now()`，没有做「时间合理性」约束（真实链要求 ≤ 未来 15s）。

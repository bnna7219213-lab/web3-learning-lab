## 二、三个直接问题的答案

### Q1：B08 与 B09 有关系么？

**有，但不是"谁在谁之上"。** 它们是**同一个联盟链上互补的两个视角**：

- B08 看的是**合约工程面**：Gas 怎么省、升级怎么演练、地址怎么登记、存储槽怎么排。
- B09 看的是**数据面**：这些工程动作在链上留下的事件，能不能被索引、被查询、被对账、被出证。

两者真正的交集是 **ERC-1967 的 `Upgraded` 事件**：B08 的代理升级演练会在链上留下 `Upgraded(impl)`，
B09 的索引器能把它解出来，于是"代理的实现版本史"第一次变成**可查询的数据**，
而不只是"某次演练的日志"。这正是 G 组断言在验的东西。

### Q2：09 需要根据 08 么？

**架构上不需要，交付上值得。**

- **不需要**：B09 的核心链路（扫块 → 过滤 → 落库 → 游标分页 → REST → 看板）在没有 B08 的情况下完全成立。
  B08 的合约不是"业务凭证"，B09 索引它属于**可选的第二事件源**，不构成前置条件。
- **值得**：因为联盟链上真正需要"可查询、可对账、可出证"的东西，除了凭证流水，
  还有**运维动作的痕迹**（谁在什么时候升级了合约、地址是怎么登记的）。
  只做 B09 不带 B08，索引出来的是"业务数据"；带上 B08，索引出来的是"业务数据 + 运维证据"。

> 实现取舍：如果 B08 的部署记录不存在，`watchSources()` 只跳过该源，不会让索引器整体失败
> —— 这保证了「软依赖」名副其实，而不是把 B08 变成 B09 的隐性前置。

### Q3：08 需要参考 07 么？

**只参考"基座"，不参考"合约"。**

- 参考的：联盟链组网、成员账户密钥、零 gas 交易参数、london 编译 profile、Besu txpool 静默丢单的坑。
- 不参考的：B07 的合约接口、B07 的元数据/出证结构（B07 那套是"凭证"，B08 这套是"工程实验"，语义不同）。
- 反过来 B08 也不该依赖 B03 的浏览器（B03 explorer 是钱包/浏览器，B08 的可观测是链上事件 + 实测报告）。
